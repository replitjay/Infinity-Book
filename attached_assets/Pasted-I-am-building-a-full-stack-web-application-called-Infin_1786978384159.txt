I am building a full-stack web application called "Infinity" — a free-to-play 
social cricket and casino gaming platform for the Indian market. 

I have attached the full Design & Development Specification PDF. Work from 
Sections 4–14 of that document. Below is the complete technical brief.

---

STACK
- Frontend: Next.js 15 (App Router), TypeScript, Tailwind CSS
- Backend: Next.js API routes + separate NestJS service for WebSocket/real-time
- Database: PostgreSQL with Prisma ORM
- Cache/Realtime: Redis (Upstash) + Socket.IO
- Auth: Phone OTP via MSG91 + Google OAuth via NextAuth
- Payments: Razorpay (virtual coin packs only)
- CDN: Cloudflare
- Analytics: GA4 + Mixpanel

7. SCORE FEED ARCHITECTURE (critical — do not skip this)

   - API key NEVER goes to the browser. Server-side only. 
     Verified absent from client bundle.
   - NestJS scheduled job polls provider every 5s during live matches, 
     60s otherwise
   - Normalise payload to internal schema, diff against last Redis state
   - Redis stores current match state with TTL
   - REST endpoint for SSR initial render (SEO-visible, fast first paint)
   - Socket.IO rooms — one per match — push deltas only (not full scorecard)
   - Browser updates score header, over strip, commentary in place
   - Feed failure state: show last-known score with visible timestamp + 
     "Reconnecting..." indicator. Never show blank or stale-as-live.
   - On match completion: persist full scorecard to PostgreSQL — 
     these become permanent indexed content pages

   For now, mock the feed with realistic static data. 
   The architecture above must be in place for the real feed to plug in.
